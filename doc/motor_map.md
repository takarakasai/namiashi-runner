# モータ / ポート対応表

`config/namiashi.toml` の内容をそのまま表にしたもの。**校正で値が変わったら
`namiashi check` の出力が最新**（あちらは設定から毎回生成している）。ここは
ベンチで手元に置く紙の代わり。

## CH348 の UART 割り当て

`nm_board/ch348/spec_rev2_0_0_asbuilt.md` §4 の as-built 確定値。

| UART | 役割 | I/F | コネクタ |
|:--:|---|---|---|
| 0 | LEG1 = **FL** | RS485 (U9) | J14 (1=B, 2=A) |
| 1 | LEG2 = **RL** | RS485 (U10) | J15 |
| 2 | LEG3 = **FR** | RS485 (U11) | J16 |
| 3 | LEG4 = **RR** | RS485 (U12) | J17 |

> **訂正 (2026-08-21):** 本表は 2026-08-20 まで UART1=FR / UART2=RL と書いて
> いたが誤り。実機は **UART1=RL / UART2=FR**。articara で実測角を可視化し、
> 脚を手で動かして対応を突き合わせて判明した（`viz_live.md`）。
>
> J14..J17 が左列 → 右列に並ぶ基板なので、**左 2 本（FL, RL）を先に配線するのが
> 自然な取り回し**になる。コード側の既定値もこれに合わせた。
>
> **`LegSlot::ALL`（FL, FR, RL, RR）とは順序が違う**点に注意。あちらは
> `quadruped_gait::LegId::ALL` と一致させる必要があり `JointVec` の添字にも
> なっているので、UART 割り当てを位置で振ってはいけない。
| 4 | ARMA（腕） | RS485 (U13) / TTL 切替 | J18 + CN3 |
| 5 | IMU | TTL 直結 | CN1 (1=+3.3V, 2=GND, 3=TX, 4=RX) |
| 6 | S.BUS | 反転 TTL (U15)、**受信専用** | CN2 (1=GND, 2=+5V, 3=RX) |
| 7 | ARMB（予備） | RS485 (U14) / TTL 切替 | J19 + CN4 |

**`/dev/ttyCH9344USB*` の番号は当てにしない。** 列挙順で決まるので物理 UART
番号とは無関係。アプリは ch9344 の `GETUARTINDEX` ioctl で引いている
（`namiashi ports` で対応が見える）。

## 脚モータ 12 軸（LKMTech MG4005）

共通: RS485 **2,000,000 baud** / torque_constant 未設定
（＝トルク API は電流 A のまま流れる）

**減速比は軸で違う。** hip / thigh は MG4005 内蔵の **10.0**、
**calf だけベルト駆動でプーリ径比 1.47 が上乗せされ、総減速比 14.7**。
脚のなかで一番負荷がかかる軸なのでそう設計されている。
設定では `MotorConfig::gear_ratio` に軸個別で持つ（未指定なら共通値）。

**符号（`sign`）は全軸 +1 ではない。**

| | hip (Roll) | thigh (Pitch) | calf (Pitch) |
|---|:--:|:--:|:--:|
| FL | +1 | +1 | +1 |
| RL | **−1** | +1 | +1 |
| FR | +1 | **−1** | **−1** |
| RR | **−1** | **−1** | **−1** |

**Roll は前後で、Pitch は左右で反転する。** 反転の軸が違うので、
左右対称だろうと決めてかかると外す。設計データ由来で、2026-08-21 に
実機で確認済み（両後脚の Roll が逆、左右の右脚 2 本の Pitch が逆）。

> **訂正 (2026-08-21):** 本表は 2026-08-20 まで **1,000,000 baud** と書いていたが誤り。
> 実機は **2 Mbps**。初通電時の id スキャンが 4 脚とも「応答なし」になり、
> 電源・A/B 極性を疑って切り分けた末に判明した。
> 2 Mbps に直したところ 4 脚とも即座に `id 1, 2, 3` が応答した。

| # | 脚 | UART | コネクタ | 関節名 | kind | **RS485 id** | 可動域 [rad] | URDF effort [N·m] |
|---|---|:--:|---|---|---|:--:|---|---|
| 1 | FL | 0 | J14 | `FL_hip_joint` | hip | **1** | −0.785 … +1.05 | 1.5 |
| 2 | FL | 0 | J14 | `FL_thigh_joint` | thigh | **2** | −2.62 … +2.62 | 1.5 |
| 3 | FL | 0 | J14 | `FL_calf_joint` | calf | **3** | −2.62 … +2.62 | 2.205 |

### 読むときの注意

- **id はバス内でのみ一意。** 4 バスとも `1, 2, 3` の繰り返しなので、id 単体では
  12 軸を区別できない。軸の identity は **(バス, id)** の組で、バス側が半分を
  担っている。取り違えの症状は「片脚だけ挙動がおかしい」になり、配線かソフトかの
  切り分けがしづらい。コネクタと id は必ずセットで確認すること。
- **hip の可動域は左右で反転**（FL/RL は −0.785…+1.05、FR/RR は −1.05…+0.785）。
  URDF の `<limit>` をそのまま写した値。
- ~~**`sign` と `zero_pose_rad` は全 12 軸まだ未校正**（+1.0 / 0.0 の推測値）。~~
  **`sign` は 2026-08-21 に確定**（上表、設計データ + 実機確認）。

  **`zero_pose_rad` は設計データの暫定値**（未検証）。伏せ姿勢で電源 ON した
  ときのオフセットで、`hip ±34° / thigh +67° / calf −160°`。

  | 脚 | hip | thigh | calf |
  |---|---:|---:|---:|
  | FL | **+43.74°** | +67° | −160° |
  | FR | **−43.74°** | +67° | −160° |
  | RL | **+49.47°** | +67° | −160° |
  | RR | **−49.47°** | +67° | −160° |

  > **hip は実機で補正した (2026-08-21)。** 設計データの ±34° を入れた状態で
  > まだずれており、**表示が 0° のとき実際は FL +0.17 / FR −0.17 /
  > RL +0.27 / RR −0.27 rad** にあった。その分をオフセットへ足してある。
  >
  > 補正量が 10〜15° と大きい。設計データの「伏せ姿勢」と、実際に電源を
  > 入れている姿勢が同じでない可能性がある。**thigh と calf は未補正**なので、
  > 同様のずれが残っているかもしれない。段階 6 の `calib zero` で 12 軸まとめて
  > 測り直すのが本筋。
  >
  > 前後で値が違う（43.74° / 49.47°）のは実機の実測どおり。左右は符号反転で対称。

  > **未検証。** 「電源 ON 時にエンコーダが 0 を指す」前提で
  > `q_model = sign * q_motor + zero_pose_rad` の `zero_pose_rad` に
  > そのまま入れている。設計データ提供者の記憶も曖昧とのことで、
  > **段階 6 の `calib zero` で実測に置き換えるまで信用しないこと。**
  > ずれていれば起立の瞬間に姿勢が破綻する。

- **モータ id は設計データを採用していない。** 設計は FL 10-12 / RL 13-15 /
  FR 20-22 / RR 23-25 だが、**これは 4 バス化より前の資料**で、実機は 4 バスとも
  `1, 2, 3`（段階 2-2 のスキャンで確認）。上表のとおり 1, 2, 3 が正。
  上の可動域も「URDF 上の値」で、実機で確かめた値ではない。
  `namiashi calib range` / `calib move` を 12 軸ぶん回すと実測値に置き換わる。

## 腕

`arm_pitch_joint` は MG4005 ではなく RC サーボ。**受信機直結**で、アプリは
駆動しない（プロポ CH9 から角度を観測するだけ）。品種は未定。

| 項目 | 値 |
|---|---|
| 可動域 | −2.3 … +0.85 rad（URDF `<limit>`） |
| effort | 6.865 N·m |
| 観測チャンネル | S.BUS CH9（`teleop.arm`） |
