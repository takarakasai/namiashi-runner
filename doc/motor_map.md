# モータ / ポート対応表

`config/namiashi.toml` の内容をそのまま表にしたもの。**校正で値が変わったら
`namiashi check` の出力が最新**（あちらは設定から毎回生成している）。ここは
ベンチで手元に置く紙の代わり。

## CH348 の UART 割り当て

`nm_board/ch348/spec_rev2_0_0_asbuilt.md` §4 の as-built 確定値。

| UART | 役割 | I/F | コネクタ |
|:--:|---|---|---|
| 0 | LEG1 = **FL** | RS485 (U9) | J14 (1=B, 2=A) |
| 1 | LEG2 = **RL** | RS485 (U10) | J15 |
| 2 | LEG3 = **FR** | RS485 (U11) | J16 |
| 3 | LEG4 = **RR** | RS485 (U12) | J17 |
| 4 | ARMA（腕） | RS485 (U13) / TTL 切替 | J18 + CN3 |
| 5 | IMU | TTL 直結 | CN1 (1=+3.3V, 2=GND, 3=TX, 4=RX) |
| 6 | S.BUS | 反転 TTL (U15)、**受信専用** | CN2 (1=GND, 2=+5V, 3=RX) |
| 7 | ARMB（予備） | RS485 (U14) / TTL 切替 | J19 + CN4 |

> **訂正 (2026-08-21):** 本表は 2026-08-20 まで UART1=FR / UART2=RL と書いて
> いたが誤り。実機は **UART1=RL / UART2=FR**。articara で実測角を可視化し、
> 脚を手で動かして対応を突き合わせて判明した（`viz_live.md`）。
>
> J14..J17 が左列 → 右列に並ぶ基板なので、**左 2 本（FL, RL）を先に配線するのが
> 自然な取り回し**になる。コード側の既定値もこれに合わせた。
>
> **`LegSlot::ALL`（FL, FR, RL, RR）とは順序が違う**点に注意。あちらは
> `quadruped_gait::LegId::ALL` と一致させる必要があり `JointVec` の添字にも
> なっているので、UART 割り当てを位置で振ってはいけない。

**`/dev/ttyCH9344USB*` の番号は当てにしない。** 列挙順で決まるので物理 UART
番号とは無関係。アプリは ch9344 の `GETUARTINDEX` ioctl で引いている
（`namiashi ports` で対応が見える）。

## 脚モータ 12 軸（LKMTech MG4005）

共通: RS485 **2,000,000 baud** / torque_constant 未設定
（＝トルク API は電流 A のまま流れる）

**減速比は軸で違う。** hip / thigh は MG4005 内蔵の **10.0**、
**calf だけベルト駆動でプーリの歯数比 28:18 が上乗せされ、総減速比 15.5556**。
脚のなかで一番負荷がかかる軸なのでそう設計されている。
設定では `MotorConfig::gear_ratio` に軸個別で持つ（未指定なら共通値）。

> **歯数から計算すること。** 28/18 = 1.5555… を 1.55 と丸めると 0.36% ずれ、
> calf の端（±2.6 rad）で約 0.5° になる。歯数は整数で誤差が無いので、
> コード側も `CALF_PULLEY_TEETH = (28.0, 18.0)` の比で持っている。
>
> **訂正 (2026-08-21):** 当初 1.47（総減速比 14.7）としていたが誤り。
> 正しくは 28:18。差は 5.8% で、calf を −2.79 rad と読んでいた場合の
> 真値は −2.64 rad（**8.8° の違い**）。それ以前に採った calf の読み値は
> すべてこの分ずれている。

**符号（`sign`）は全軸 +1 ではない。**

| | hip (Roll) | thigh (Pitch) | calf (Pitch) |
|---|:--:|:--:|:--:|
| FL | +1 | +1 | +1 |
| RL | **−1** | +1 | +1 |
| FR | +1 | **−1** | **−1** |
| RR | **−1** | **−1** | **−1** |

**Roll は前後で、Pitch は左右で反転する。** 反転の軸が違うので、
左右対称だろうと決めてかかると外す。設計データ由来で、2026-08-21 に
実機で確認済み（両後脚の Roll が逆、左右の右脚 2 本の Pitch が逆）。

> **訂正 (2026-08-21):** 本表は 2026-08-20 まで **1,000,000 baud** と書いていたが誤り。
> 実機は **2 Mbps**。初通電時の id スキャンが 4 脚とも「応答なし」になり、
> 電源・A/B 極性を疑って切り分けた末に判明した。
> 2 Mbps に直したところ 4 脚とも即座に `id 1, 2, 3` が応答した。

### 読むときの注意

- **id はバス内でのみ一意。** 4 バスとも `1, 2, 3` の繰り返しなので、id 単体では
  12 軸を区別できない。軸の identity は **(バス, id)** の組で、バス側が半分を
  担っている。取り違えの症状は「片脚だけ挙動がおかしい」になり、配線かソフトかの
  切り分けがしづらい。コネクタと id は必ずセットで確認すること。
- **hip の可動域は CAD から決めた運用制限**で、URDF の `<limit>` ではない。

  | 脚 | 可動域 |
  |---|---|
  | 左足 FL / RL | **−60° … +45°** |
  | 右足 FR / RR | **−45° … +60°** |

  > **メカ端まで振ってはいけない。** hip Roll のメカ端は非常に広く、そこまで
  > 振ると**ケーブルが破断しうる**。機械が止めてくれないので、ソフト側で
  > 先に止めるしかない。`calib range` で手測りするのも避けること
  > （端まで動かす作業そのものが危険）。
  >
  > **訂正 (2026-08-21):** URDF は左右が逆だった。大きさ（45° / 60°）は
  > 合っていたが割り当てが入れ替わっており、左足に右足の値が入っていた。
- ~~**`sign` と `zero_pose_rad` は全 12 軸まだ未校正**（+1.0 / 0.0 の推測値）。~~
  **`sign` は 2026-08-21 に確定**（上表、設計データ + 実機確認）。

  **`zero_pose_rad` は伏せ姿勢で電源 ON したときのオフセット。**
  hip は実機で補正済み、thigh / calf は設計データのまま（未検証）。

  | 脚 | hip | thigh | calf |
  |---|---:|---:|---:|
  | FL | **+24.26°** | +67.00° | **−154.52338°** |
  | FR | **−24.26°** | +67.00° | **−154.52338°** |
  | RL | **+18.53°** | **+53.29°** | **−154.52338°** |
  | RR | **−18.53°** | **+47.57°** | **−154.52338°** |

  > **calf は突き当て位置が基準。** 電源 ON = 突き当て = `q_abs 0` なので、
  > オフセットは突き当ての モデル角そのもの。**可動域の下限と同じ値**になる。
  >
  > **訂正 (2026-08-21):** 当初の −160° は**二重に古い情報**で計算されていた
  > （旧減速比 14.7 + 旧突き当て角）。最新の可動域 ±154.52338° に合わせて
  > 置き直した。
  >
  > 突き当てが可動域より外側（使用範囲にマージンがある）なら、その分ずれる。

  > **thigh は前後で水平の定義が違う。可動域の都合による設計。**
  >
  > | | 水平のときのモデル角 |
  > |---|---|
  > | 前脚 FL / FR | **−π/2** |
  > | 後脚 RL / RR | **+π/2** |
  >
  > 前後の表示が π ずれていても異常ではない。**知らないと「片方が壊れている」
  > と誤診する。**
  >
  > **後脚の thigh は実機で補正した (2026-08-21)。** 水平のとき RL が +1.81、
  > RR が +1.91 と過大だったので、その分をオフセットから引いた。
  > 前脚は −1.57 で期待値どおりだったため無変更。
  > RL と RR で値が違う（53.29° / 47.57°）のは実測どおり。

  > **hip は実機で補正した (2026-08-21)。** 設計データの ±34° を入れた状態で
  > **表示が実際より過大**になっており、実際が 0° のとき表示が
  > FL +0.17 / FR −0.17 / RL +0.27 / RR −0.27 rad を指していた。
  > その分をオフセットから**引いて**ある。
  >
  > ```
  > q_model = sign * q_abs + zero_pose_rad
  > 表示が +0.17 過大 → zero_pose_rad から 0.17 を引く
  > ```
  >
  > 補正量が 10〜15° と大きい。設計データの「伏せ姿勢」と、実際に電源を
  > 入れている姿勢が同じでない可能性がある。**thigh と calf は未補正**なので、
  > 同様のずれが残っているかもしれない。段階 6 の `calib zero` で 12 軸まとめて
  > 測り直すのが本筋。
  >
  > 前後で値が違う（24.26° / 18.53°）のは実機の実測どおり。左右は符号反転で対称。

  > **基準の性質が軸で違う。これが実測のずれ方を説明する。**
  >
  > | 軸 | 基準 | 再現性 | 実測のずれ |
  > |---|---|---|---|
  > | hip / thigh | **伏せ姿勢**での電源 ON | 姿勢を人が作るので毎回変わる | **10〜19°** |
  > | calf | **メカ的な突き当て**からのオフセット | 機構が決めるので再現する | 設計変更も無く、誤りの可能性は低い |
  >
  > hip と thigh が大きくずれていたのに calf は信用できる、という非対称は
  > ここから来る。**calf の −160° は突き当て基準なので触らない。**
  >
  > 逆に hip / thigh は「どの姿勢で電源を入れたか」に丸ごと依存する。
  > 電源投入の姿勢を変えたら測り直すこと。

- **モータ id は設計データを採用していない。** 設計は FL 10-12 / RL 13-15 /
  FR 20-22 / RR 23-25 だが、**これは 4 バス化より前の資料**で、実機は 4 バスとも
  `1, 2, 3`（段階 2-2 のスキャンで確認）。上表のとおり 1, 2, 3 が正。

- **可動域の出所は軸で違う。**

  | 軸 | 出所 | `calib range` で測る？ |
  |---|---|---|
  | hip | **CAD**（ケーブル保護の運用制限） | **測らない。** 端まで振るのが危険 |
  | thigh | URDF の値（実機未確認） | **測る**（段階 4） |
  | calf | **設計のメカ端 ±154.52338°** | **測らない。** 手測りは必ず狭くなる |

  calf を手で測ると (a) 突き当てまで押し込めない (b) `--margin` がさらに引かれる、
  で今より狭い値になり、`start` ポーズがクランプされてしまう。

  **calf だけ可動域が違う。** 2026-08-21 の設計変更で **±154.52338°
  (±2.6969 rad)**。thigh の ±2.62 rad (±150.11°) と混ぜないこと。

  > **初期姿勢 `start` の前脚 calf −162° がまだ収まらない（+7.48° 超過）。**
  >
  > オフセットは最新値に置き直したが、`start` / `standby` のポーズは設計
  > データのまま。**オフセットが二重に古かった以上、ポーズ側も同じ理由で
  > 古い可能性が高い**（`.misa` と `misarta.toml` の両方）。
  >
  > 現状 `start` はクランプされてスタート台に収まらない。**要確認。**

## 可動域を逸脱したときの扱い【未解決】

**制御中に外力を受けると、上表の可動域を超えることがある。** 指令は
`min_rad`/`max_rad` にクランプされるので**こちらから超えることはない**が、
押された・転んだ場合は超えうる。

**超えた状態で脱力させるのは危険。** 特に hip は、メカ端まで余裕がある一方で
ケーブルが先に限界を迎える。脱力するとそのまま外力に任せることになり、
自力で戻れない。

現状の挙動:

| きっかけ | 挙動 | 逸脱時に安全か |
|---|---|---|
| S.BUS 受信断・フェイルセーフ | 速度 0・その場起立（**脱力しない**） | 比較的よい。姿勢を保とうとする |
| **`Ctrl-C`** | **全軸脱力** | **危うい。** 逸脱したまま力が抜ける |
| モータ電源 OFF | 脱力 | 同上 |

`Ctrl-C` の脱力は「暴走したら力を抜く」という発想で、それ自体は正しい。
しかし**逸脱時にはむしろ戻してから抜きたい**。両立させるなら、脱力の前に
可動域内へ戻す動作を挟むことになるが、暴走時にそれをやると危険が増す。
**トレードオフであり、決めきれていない。**

判断の材料になる実測がまだ無い（段階 7 以降で逸脱が実際に起きるか）。
それまでは**脚を浮かせた状態でしか運転しない**という運用で回避する。
